1. What Is This System?

The OCTS Employee Management Portal is a secure, private internal web portal custom engineered for Oceanic Construction and Technical Services (OCTS). It transitions the company away from slow, error-prone manual Excel trackers and paper files into a robust digital environment.

Main business objectives solved by this system:

  • Manpower Database: Centralized profiles for all offshore workers.
  • Smart Certification Expiries: Active tracking of crucial safety certs (BOSIET, H2S, STCW) and passports.
  • Deployment Logs: Immediate visibility into who is currently active, signed off, available, or cancelled.
  • Salary Encryption: Strictly controlled per-day wage tracking visible only to the Master Admin (Anil).
  • Secure Document Management: Drag-and-drop storage for CVs, photos, passports, and medical certificates directly mapped to employee folders.
  • One-Click Excel Sync: Instant export of formatted manpower sheets for client submission.
  • Audit Trail: Every single modification, registration, deletion, and login is logged with timestamps and names.
No Cloud Dependencies Needed
The app runs 100% locally on your computer. You do not need any third-party cloud subscriptions or paid hosting. It is entirely private to your office.

2. What Has Been Built — Feature Overview

The system is packed with production-ready business features. Here is an overview of what has been fully tested and delivered:

📁 Employee Profiles

Captures over 55 distinct fields including INDOS, passport, Aadhar, safety validations, medical certificates, and deployment timelines. Autogenerates incrementing serial numbers.

🔐 Three-Tier Security Roles

Limits data access. Admins can view and edit everything; Clerks can add records and edit details (but cannot view/edit salaries); Viewers get a read-only search interface.

📑 Paperless Uploads

Uploads up to 7 document formats per employee. Nginx handles fast binary streaming for files up to 20MB directly onto server volumes.

📊 Live Statistics

Dashboard updates dynamic counts of active/available workers and compiles designation breakdowns in clean charts, fully responsive on mobile screen views.

3. How the System Works (Architecture)

The system operates in isolated "containers" using Docker. This isolates the app from other software installed on your PC, ensuring it won't break if Windows updates or if other programs are installed.

┌───────────────────────────────────────────────────────────────────┐ │ Company Computer │ │ │ │ ┌──────────────────────┐ ┌──────────────┐ │ │ │ Frontend │ │ Backend │ │ │ │ (Nginx Web Entryway) ├───────►│ (API Server │ │ │ │ Port 80 (HTTP) │ │ Port 8000) │ │ │ │ │◄───────┤ │ │ │ └──────────┬───────────┘ └──────┬───────┘ │ │ │ │ │ │ │ /api relative routes │ │ │ ▼ ▼ │ │ [Employee Docs Volume] ┌───────────────┐ │ │ (backend/employee_docs) │ PostgreSQL │ │ │ │ Database │ │ │ │ Port 5432 │ │ │ └───────────────┘ │ └─────────────────────────────────┬─────────────────────────────────┘ │ ┌───────────────────────────┴───────────────────────────┐ │ Any browser on the local WiFi/LAN network accesses: │ │ │ │ - http://localhost (on the same PC) │ │ - http://192.168.x.x (from mobile/other PCs) │ └───────────────────────────────────────────────────────┘

💡 Unified Port 80 Entry (Nginx Proxy)

To enable flawless office network access, the frontend container acts as a reverse proxy on Port 80 (standard HTTP web port):

  • Static Assets: Serves the React frontend.
  • API Route forwarding: Requests starting with /api are forwarded automatically to the backend on port 8000.
  • Media Downloads: Requests to /uploads serve files directly from the local volume.
  • Network access benefits: Other computers and mobile phones connect to the main computer's IP address directly. Since everything is routed through Port 80, there are no CORS errors, and Windows Firewall does not block the mobile browsers.

4. How to Start & Stop the Portal

Manage the app's lifetime via simple commands in Windows PowerShell.

▶️ Launching the Application

  1. Open Docker Desktop. Wait for the green engine icon on the bottom left to show it is active.
  2. Right-click the Start menu and select Windows PowerShell.
  3. Enter the following commands: 
    cd C:\Users\abhay\Desktop\OCTS
docker compose up -d
  4. Open any web browser and go to http://localhost.

⏹️ Stopping the Application

If you need to turn off the portal (e.g. before copying files or backing up the PC):

cd C:\Users\abhay\Desktop\OCTS
docker compose down

5. First-Time Setup on the Company Computer

If you ever move the application folder to a new company computer, follow this setup sequence once:

  1. Install Docker: Download and install "Docker Desktop for Windows" from the official site. Install all defaults, restart your PC, and complete the sign-in prompt.
  2. Copy Files: Move the entire OCTS directory to C:\Users\[YourUsername]\Desktop\OCTS.
  3. First Run Initialization: Run the terminal as administrator and type: 
    cd C:\Users\abhay\Desktop\OCTS
docker compose up -d --build
    Note: The first build fetches compiler dependencies and might take 5-10 minutes. Subsequent starts take less than 20 seconds.
  4. Verify Containers: Ensure all three services are green: 
    docker compose ps
Auto-Start on PC Bootup
To make the portal start automatically when the computer is turned on: Open Docker Desktop settings -> General -> Toggle "Start Docker Desktop when you sign in to your computer" to ON.

7. The Admin Dashboard — Full Walkthrough

When logging in as Anil, you land on the **Operations Dashboard** which includes:

  • Stats row: Live counter blocks displaying Total Employees, Active Deployments, Available Workers, Signed Off, and Cancelled statuses.
  • Designation Metrics: An auto-updating horizontal bar chart illustrating the distribution of manpower across designations (Riggers, Scaffolders, Welders, etc.).
  • Quick actions panel: Shortcut buttons to register workers, launch advanced search, or open the full database list.
  • Recent activity notifications: The bell icon in the top header pops open to show the latest 5 audit entries (e.g. "Clerk uploaded document for employee X") for quick review.

8. The Clerk Dashboard — What a Clerk Can Do

The Clerk Dashboard is a streamlined control center designed for administrative assistants who register workers and manage documents.

Clerks are authorized to:

  • Add new workers and enter initial salaries.
  • Edit employee information (except salary values, which lock after creation).
  • Manage document uploads (CVs, Passports, BOSIETs, Photos).
  • Search the entire employee directory.

Clerks are blocked from: deleting workers, changing salaries, viewing system log records, and downloading user accounts.

9. The Viewer Dashboard — What a Viewer Can Do

Designed for managers or partners who only need read-only access. It provides search functionality and basic details for employees, but keeps financial information secure:

  • Completely Read-Only: Cannot register or edit records. No "Edit" or "Delete" actions appear.
  • Salary Shielding: Per-day wage stats are completely stripped from the UI. Viewer templates do not request this data from the backend.
  • Document Access: Can view and download PDFs, resumes, and safety certifications.

10. User Management — Creating Staff Accounts

Only the Master Admin can manage office user accounts. This screen lists all staff accounts and allows creating, editing, and disabling them.

👤 Creating a New Account

  1. Navigate to User Management via the left sidebar.
  2. Click the Create New User button.
  3. Fill in the fields (Name, Email, Login Username, Password, and Role selection).
  4. Click Save. The user can log in immediately.

🚫 Locking Out Staff (Deactivation)

When an employee leaves the company, do not delete their account, as it is needed to preserve history in the audit logs. Instead, deactivate it:

  1. Click Edit on the user's row.
  2. Toggle the Active checkbox to **OFF**.
  3. Click Save Changes. Their login session is immediately blocked.

12. Salary System Controls

Salary values are highly sensitive. The database tracks per-day wages (₹) using role-based access control:

  1. During Registration: The clerk inputting the new profile can enter an initial per-day salary.
  2. Post-Creation Lock: Once the profile is saved, the salary field is hidden from clerks. They cannot see or change it.
  3. Admin Exclusivity: Only Admin accounts can view and edit the salary field on the employee edit screen.
Excel Salary Security
The per-day salary column is automatically omitted from the master Excel sheet if a Clerk attempts to export it. Only when Anil (Admin) exports the sheet will the salary column be generated.

15. Audit Logs — Who Did What and When

The audit log acts as a permanent ledger of system activity. To view it, log in as Admin and click Audit Logs in the left sidebar.

Common events logged automatically:

  • employee_created: Displays name of creator, timestamp, and new employee ID.
  • employee_updated: Shows the exact fields changed (e.g. "Changed status from Available to Active").
  • employee_deleted: Logs who initiated a deletion.
  • user_login_failed / user_login_success: Records login attempts with IP addresses for security tracking.

16. Day-to-Day Operations & Network Access

📱 Accessing on Mobile Devices & Other PCs (Local Wi-Fi)

Because the app runs inside a secure Nginx reverse proxy on Port 80, anyone in the office can connect using their phone or laptop without setting up additional servers:

  1. Get the Server IP: On the main PC running the portal, open PowerShell and type: 
    ipconfig
    Find the **IPv4 Address** (e.g. 192.168.29.232).
  2. Connect Devices: Connect the mobile phone or secondary laptop to the same office Wi-Fi network.
  3. Access the Portal: Open Chrome/Safari on the phone and go to: 
    http://192.168.29.232
    (Make sure to replace this with your actual IPv4 address. Do not append ports like :8000 or :5173).
  4. The interface is fully optimized for mobile devices. The navigation menu will automatically collapse into a mobile-friendly hamburger menu.

🌐 Temporary Public Access (Ngrok & Localhost.run)

If Anil needs to check the portal from outside the office (e.g. at home or a client meeting), you can temporarily publish the site using a secure tunnel. Since Nginx handles everything on Port 80, you must tunnel Port 80:

Option A: Using Ngrok (Recommended)

1. Download Ngrok and link your auth token in PowerShell:

ngrok config add-authtoken <token>

2. Open a tunnel to port 80:

ngrok http 80

3. Share the secure URL (e.g. https://xyz.ngrok-free.app).

Option B: Using Localhost.run (No Install)

Windows 10/11 has SSH built-in. Open PowerShell and run:

ssh -R 80:localhost:80 nokey@localhost.run

2. The command will output a public URL (e.g. https://octs.lhr.life).

3. Copy and open this URL on any phone or PC connected to the internet.

17. Data Backup & Recovery

Since the database is running in a Docker container and files are stored locally, backup is simple. Backup these two items regularly:

📦 1. Database Backups (SQL Export)

Run this command in PowerShell to export the database to a file:

cd C:\Users\abhay\Desktop\OCTS
docker exec -t octs-postgres_db-1 pg_dump -U octs_user octs_db > octs_backup_$(Get-Date -Format 'yyyy-MM-dd').sql

This generates a file like octs_backup_2026-06-14.sql. Copy this file to a USB drive or cloud folder for safekeeping.

📁 2. Backup Uploaded Files

Copy the directory containing uploaded documents to a secure backup drive:

C:\Users\abhay\Desktop\OCTS\backend\employee_docs\

♻️ Restoring from Backup

If you need to restore the system on a new PC:

  1. Copy your SQL backup file to C:\Users\abhay\Desktop\OCTS and rename it to restore_backup.sql.
  2. Run this command in PowerShell: 
    cd C:\Users\abhay\Desktop\OCTS
cat restore_backup.sql | docker exec -i octs-postgres_db-1 psql -U octs_user -d octs_db
  3. Copy your backed-up employee_docs folder back to C:\Users\abhay\Desktop\OCTS\backend\employee_docs\.

18. Troubleshooting Guide

❌ Portal does not load (http://localhost is blank)

  • Make sure Docker Desktop is open and showing the green "running" status.
  • Open PowerShell and run: 
    docker compose ps
    If any service is stopped, restart them: 
    docker compose up -d

❌ Mobile phone shows "Login Failed"

  • Make sure both the phone and PC are connected to the same Wi-Fi network.
  • Ensure you entered the correct IP address in your mobile browser (e.g. http://192.168.29.232).
  • Do not append :8000 or :5173 to the URL. Connect to the IP address directly.

❌ Upload fails with "File Too Large" error

  • Document uploads are capped at 20 MB. If your PDF is larger, search for "compress PDF" online and reduce the file size before uploading.

19. Security Best Practices

  • Change Admin Passwords: Do not leave the default Admin@OCTS#2020 password active. Change it immediately.
  • Unique Accounts: Create separate accounts for clerks and viewers. Do not share login credentials, as this maintains the integrity of the audit logs.
  • Deactivate Accounts: Deactivate staff accounts immediately when an employee leaves the company.
  • Offsite Backups: Do not store database SQL backups on the same computer. Copy them to a USB drive or secure cloud storage.
